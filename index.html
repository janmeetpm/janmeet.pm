01 about
➜so what do you actually own?
◆The parts of a conversational agent that decide whether it actually works. Nugget's agent handles a company's customer support — in chat and over the phone — in place of a support team. Underneath it are separate modules, and I own the ones that decide the outcome: the piece that works out what step to take next, the piece that looks up the company's own policies before it answers, the piece that chooses which AI model handles which conversation and what that costs, and the tests that catch the agent doing something it shouldn't before a customer does. Four questions run all of it: does it follow the rules, is it fast enough, what does one conversation cost, and how much of it have we actually tested. I'm the founding AI product manager on it. Nugget is built inside Eternal — the group behind Zomato and Blinkit.
➜how do you know which part is broken?
◆I take it apart until I do. An agent that goes wrong doesn't crash. It sounds fluent, quietly skips a step, and the conversation still looks fine from the outside — so I read the transcripts turn by turn until I can name the exact step it dropped. Most of what I've built came out of that habit. I built the testing system because I was tired of guessing. I moved the company-knowledge layer into a screen the support team can edit themselves, instead of filing a ticket to engineering every time a policy changes. I build the prototype myself rather than describe it in a document. Before AI, four years on ranking and ads at Zomato and Blinkit at consumer scale — which is where I learned that how fast a thing answers is a product decision, not an engineering detail.

02 systems · 5 entries

five problems, written decision-first.

The decision is the part that transfers to a different domain. The metric only proves I stayed long enough to see it land.

sys-01evals
built hands-on

an eval harness for agents that fail silently

problem
An agent doesn't crash when it goes wrong. It skips a step, sounds fluent, and the task still looks complete. Conversation-level scores cannot see that.
decision
Score at the node level, not the conversation level. A versioned test-case suite, adversarial prompts built to push the agent off-flow, and a rubric reporting which specific workflow nodes get skipped per batch — plus regression gating, so a prompt fix can't quietly break a solved case.
result
Failure frequency became a ranked fix list instead of a vibe. Regressions get caught before a tenant finds them.
sys-02adherence
owned the design

raising instruction adherence without a bigger model

problem
Enterprise agents fail on adherence long before they fail on intelligence. A policy prompt with twelve rules reliably loses rules four through nine somewhere mid-conversation.
decision
Treat adherence as an architecture problem, not a prompting problem. Decompose monolithic prompts into explicit flow nodes with per-node context, constrain tool schemas so the model can't improvise a shape, put deterministic guardrails on the branches carrying real risk, and let node-level evals point at exactly which rule is being dropped.
result
Off-policy behaviour became a measurable, addressable list rather than a reason to escalate to a more expensive model.
sys-03inference
economics

making cost per interaction the roadmap constraint

problem
An agent's unit economics are set at the architecture layer. If revenue per inference doesn't clear cost per interaction at real concurrency, no downstream product work saves it.
decision
Evaluate on the cost–latency curve at concurrency, not on single-call quality. Comparative simulations across model choice, vendor mix and pipeline configuration — routing cheap traffic to small models and reserving the frontier model for the turns that need it.
result
Cut per-minute production cost of the full stack to a fraction of where it started, which changed which customer segments were viable to serve at all.
sys-04retrieval · kg
built hands-on

grounding that non-engineers can own

problem
Off-policy answers are usually a knowledge problem, not a model problem. But every knowledge fix routed through engineering — so the people who actually knew the policy couldn't apply it.
decision
Ship the knowledge layer as a product surface. Document ingestion, entity and relationship extraction into a knowledge graph, versioned KB updates, retrieval at answer time — behind an interface a tenant ops team can operate without a deploy.
result
Off-policy responses fell, and knowledge ownership moved to the teams closest to the policy.
sys-05architecture
owned the eval

cascaded pipeline vs. native speech-to-speech

problem
Speech-to-speech models collapse the latency ladder — and give up the observability and per-hop control that a cascaded VAD→STT→LLM→TTS pipeline gives you.
decision
Price the trade instead of benchmarking it. What you lose in barge-in control, dialogue-state inspection and per-hop debuggability, set against what you gain in turn latency — segmented by agent class rather than decided globally.
result
Shipped as a per-class roadmap decision: which agent classes could move to speech-to-speech, and which had to keep the cascade.
